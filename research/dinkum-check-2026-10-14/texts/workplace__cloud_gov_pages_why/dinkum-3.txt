## Why static websites?

Pages generates static websites rather than running a more complicated content management system (CMS) like Drupal or WordPress. And static websites have a fair bit going for them:

- **Less complexity and vulnerability:** Skip the traditional CMS and you skip the headaches that come with it, like maintaining server applications (no PHP or Apache / IIS), plus database scaling and redundancy. A production-level static site generally needs one simple static file server or service, not dozens. So the whole website's easier to look after and has fewer vulnerabilities.

- **Update content without writing code:** Static websites often keep their content in simple text files that anyone on the team can edit. With the GitHub editor, any team member can make basic edits to their text files, whether or not they've ever written a line of code.

- **Easy to host and maintain:** Hosting static website files on Pages is dead easy. And through Pages you can make use of scaling services like Amazon S3 without any fuss, where you only pay for what you use.

- **Fully customisable:** Designers and developers can shape static websites into whatever they like, without having to strip out CMS-provided features and defaults first. You can build all sorts of sites with them, from organisation homepages or intranets to pre-generated web application program interfaces that display data from a separate server.
