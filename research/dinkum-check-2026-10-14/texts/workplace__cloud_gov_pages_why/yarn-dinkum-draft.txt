## Why static websites?

Pages generates static websites rather than using a more complicated content management system (CMS) like Drupal or WordPress. Static websites have a fair few things going for them:

- **Less complexity and vulnerability:** Steer clear of a traditional CMS and you steer clear of headaches like keeping server applications running (no PHP or Apache / IIS), on top of database scaling and redundancy. Production-level static sites generally need one simple static file server or service, not dozens. So the whole website is easier to look after and has fewer vulnerabilities.

- **Update content without writing code:** Static websites often keep their content in simple text files that anyone on the team can edit. With the GitHub editor, any team member can do basic edits to their text files, whether or not they’ve ever written a line of code.

- **Easy to host and maintain:** It’s flamin’ easy to host static website files on Pages. Through Pages you can make the most of scaling services like Amazon S3, where you only pay for what you use.

- **Fully customizable:** Designers and developers can customise static websites into whatever shape they like without having to rip out the features and defaults a CMS comes with. Static sites can be used to build all sorts of sites, from organisation homepages or intranets to pre-generated web application program interfaces that display data from a separate server.
