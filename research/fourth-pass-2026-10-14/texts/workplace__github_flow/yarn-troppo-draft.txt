## Introduction

Okay, so. GitHub flow is a lightweight, branch-based workflow, nothin' fancy. And it's not just for the developers, either: the GitHub flow's good for every man and his dog. Here at GitHub, for instance, we run our [site policy](https://github.com/github/site-policy), our [documentation](https://github.com/github/docs), and even our [roadmap](https://github.com/github/roadmap) on GitHub flow.

## Prerequisites

Before ya kick off with GitHub flow, you'll need two things: a GitHub account and a repository. Haven't got an account? The drum on settin' one up is at [Creating an account on GitHub](/en/account-and-profile/how-tos/account-management/creating-an-account-on-github). No repository yet? Have a squiz at [Quickstart for repositories](/en/repositories/creating-and-managing-repositories/quickstart-for-repositories). Reckon you'd rather pitch in on an existing repository? Then [Finding ways to contribute to open source on GitHub](/en/get-started/exploring-projects-on-github/finding-ways-to-contribute-to-open-source-on-github) is where ya wanna be.

## Following GitHub flow

> \[!TIP]
> You can knock over every single step of GitHub flow in the GitHub web interface, on the command line and [GitHub CLI](https://cli.github.com), or in [GitHub Desktop](/en/desktop), whatever takes yer fancy. For the full rundown on the tools you can use to hook up to GitHub, see [Connecting to GitHub](/en/get-started/using-github/connecting-to-github).

### Create a branch

First up, create a branch in yer repository. Give it a short name that says what it's about, and yer collaborators can tell what's on the go at a glance, no detective work needed. Somethin' like `increase-test-timeout` or `add-code-of-conduct`. For more on that, see [Managing branches within your repository](/en/pull-requests/how-tos/commit-changes/managing-branches-within-your-repository).

Creatin' a branch gives ya yer own patch to work in without touchin' the default branch. And as a bonus, it gives yer collaborators a chance to run their eye over yer work.

### Make changes

Now, on yer branch, go for yer life and make whatever changes ya like to the repository. For the how-to, see [Creating new files](/en/repositories/working-with-files/managing-files/creating-new-files), [Editing files](/en/repositories/working-with-files/managing-files/editing-files), [Renaming a file](/en/repositories/working-with-files/managing-files/renaming-a-file), [Moving a file to a new location](/en/repositories/working-with-files/managing-files/moving-a-file-to-a-new-location), or [Deleting files in a repository](/en/repositories/working-with-files/managing-files/deleting-files-in-a-repository).

Yer branch is a safe spot to muck around in. Stuff somethin' up? No worries: ya can revert yer changes, or push a few more changes to fix the stuff-up. None of yer changes'll get anywhere near the default branch till ya merge yer branch.

Commit and push yer changes to yer branch. Give every commit a message that says what it does, so you and whoever rocks up later can suss out what changes are in that commit. Short and sweet does it: `fix typo` or `increase rate limit`.

Ideally, each commit's one self-contained, complete change, nothin' else tagging along. That way, if ya change yer mind and go a different way, revertin' yer changes is a piece of piss. Say you're keen to rename a variable and add a few tests: chuck the variable rename in one commit and the tests in another commit. Down the track, if ya want to keep the tests but ditch the variable rename, ya just revert the one commit that had the variable rename in it. Bung the variable rename and the tests in the same commit, though, or smear the variable rename across a heap of commits, and you'll be workin' a whole lot harder to revert yer changes.

Every time ya commit and push yer changes, ya back up yer work to remote storage. So ya can get at yer work from any device ya like. It also means yer collaborators can see what you've been up to, answer questions, and throw in suggestions or contributions of their own.

Then just keep on makin', committin', and pushin' changes to yer branch till you're ready to ask for feedback.
