A **`cookie`** (also called a web `cookie` or browser `cookie`, and no, not the kind of bikkie you dunk in your cuppa; sadly, you can't eat these bikkies) is a little bit of data a server sends to a user's web browser. The browser can hang on to `cookies`, make new ones, change the ones it's already got, and send them back to the same server with later requests. `Cookies` let web applications keep small amounts of data and remember state information; out of the box, the HTTP protocol is [stateless](/en-US/docs/Web/HTTP/Guides/Overview#http_is_stateless_but_not_sessionless).

In this article we'll have a look at the main things `cookies` get used for, go through the best ways to use them, and check out what they mean for privacy and security.

## What cookies are used for

Usually the server uses what's in the HTTP `cookies` to work out whether different requests are coming from the same browser/user, and then sends back a personalised or a one-size-fits-all response, whichever suits. Here's how a basic user sign-in system works:

1. The user sends their sign-in details to the server, say by filling out a form.
2. If the details are right, the server updates the UI to show the user's signed in, and sends back a `cookie` with a session ID in it that keeps track of their sign-in status on the browser.
3. Later on, the user heads to a different page on the same site. The browser sends the `cookie` with the session ID along with that request, to show it still reckons the user's signed in.
4. The server checks the session ID and, if it's still good, sends the user a personalised version of the new page. If it's not, the session ID gets deleted and the user gets a generic version of the page (or maybe an "access denied" message and a request to sign in again).

![visual representation of the above sign-in system description](/shared-assets/images/diagrams/http/cookies/cookie-basic-example.png)

`Cookies` are mainly used for three things:

- **Session management**: User sign-in status, what's in the shopping trolley, game scores, or any other details about the user's session that the server needs to remember.
- **Personalisation**: User preferences like display language and UI theme.
- **Tracking**: Recording and analysing what users get up to.

### Data storage

Back in the early days of the web, when there wasn't any other option, `cookies` got used for all sorts of client-side data storage. These days the modern storage APIs are the way to go, for example the [Web Storage API](/en-US/docs/Web/API/Web_Storage_API) (`localStorage` and `sessionStorage`) and [IndexedDB](/en-US/docs/Web/API/IndexedDB_API).

They're built with storage in mind, never send data to the server, and don't have the other downsides of using `cookies` for storage:

- Browsers usually cap how many `cookies` you can have per domain (it depends on the browser, but generally it's in the hundreds), and how big each `cookie` can be (usually 4KB). Storage APIs can hold heaps more data.
- `Cookies` get sent with every single request, so they can slow things down (for example on a dodgy mobile data connection), especially if you've got a lot of `cookies` set.

> [!NOTE]
> To have a squiz at stored `cookies` (and any other storage a web page is using) you can use the [Storage Inspector](https://firefox-source-docs.mozilla.org/devtools-user/storage_inspector/index.html) in Firefox Developer Tools, or the [Application panel](https://developer.chrome.com/docs/devtools/progressive-web-apps) in Chrome Developer Tools.

## Creating, removing, and updating cookies

Once it gets an HTTP request, a server can send one or more [`Set-Cookie`](/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie) headers back with the response, and each one sets its own `cookie`. You set a `cookie` by giving it a name-value pair, like this:

```http
Set-Cookie: <cookie-name>=<cookie-value>
```

This HTTP response tells the browser that gets it to store a couple of `cookies`:

```http
HTTP/2.0 200 OK
Content-Type: text/html
Set-Cookie: yummy_cookie=chocolate
Set-Cookie: tasty_cookie=strawberry

[page content]
```
