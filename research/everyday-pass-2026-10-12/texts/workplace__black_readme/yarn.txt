> “Any colour you like.”

_Black_ is the no-nonsense Python code formatter. By using it, you agree to hand over
control of all the fiddly bits of hand-formatting. In return, _Black_ gives you speed,
the same result every time, and freedom from `pycodestyle` nagging you about formatting.
You'll save time and brainpower for the stuff that actually matters.

Blackened code looks the same no matter whose project you're reading. After a while you
stop noticing the formatting and can focus on what the code actually does.

_Black_ makes code review quicker by producing the smallest diffs possible.

Have a squiz at the [PyCon 2019 talk](https://youtu.be/esZLCuWs_2Y) to find out more.

## Installation and usage

### Installation

You can install _Black_ by running `pip install black`. It needs Python 3.10+ to run.
If you want to format Jupyter Notebooks, install it with
`pip install "black[jupyter]"`.

If you want to run _Black_ without installing Python, grab one of the
PyInstaller-built standalone executables from the
[latest GitHub release](https://github.com/psf/black/releases/latest).

### Usage

To get cracking straight away with sensible defaults:

```sh
black {source_file_or_directory}
```

If running it as a script doesn't work, you can run _Black_ as a package:

```sh
python -m black {source_file_or_directory}
```

There's more info in our docs:

- [Usage and Configuration](https://black.readthedocs.io/en/stable/usage_and_configuration/index.html)

_Black_ is already [successfully used](https://github.com/psf/black#used-by) by heaps of
projects, big and small. _Black_ has a thorough test suite, with fast parallel tests,
and our own auto formatting and parallel Continuous Integration runner. Now that we're
stable, you shouldn't expect big formatting changes down the track. Style changes will
mostly be in response to bug reports and to support new Python syntax. For more info,
check out [The Black Code Style](https://black.readthedocs.io/en/stable/the_black_code_style/index.html).

Also, as a safety check that slows things down a bit, _Black_ will make sure the
reformatted code still produces a valid AST that's effectively the same as the
original (see the
[Pragmatism](https://black.readthedocs.io/en/stable/the_black_code_style/current_style.html#ast-before-and-after-formatting)
section for the details). If you're feeling confident, use `--fast`.
