# Aussiefy v4 schema draft 20261114-r1

Proposal for site review. Production v3 remains active; this is not a freeze, release or proof that the v4 runtime is implemented. The examples are explicitly illustrative proposals, including augmented real v3 data, not real v4 emitter fixtures. Real v4 fixtures and semantic/property checks are required before activation.

The six schemas are self-contained JSON Schema 2020-12. All schemas pass the metaschema check. Six change illustrations, two discovery pages and a selection example validate; their source/output/mask bounds and option-key uniqueness were checked.

## Normative intent

- Rich and compact entry cards gain headword_key. It uses the existing engine headword comparison rule: lower-case, normalised whitespace/apostrophes and one leading a/an/the removed, retaining punctuation and hyphens. The site owns any further word-page folding. No headword spelling or permanent ID is renamed.
- other_sense is an optional curator note on an entry. Ambiguous everyday forms are recognised as Australian only with independently supported sense/frame/context evidence; otherwise recognition abstains. Active and held-back Australian-reading entries can be kept; omit and general/other-variety forms cannot.
- Changes add kept, held and personal. All changes have reading (a concept and its complete plain name, or null) and ruled_out; word changes also have option_key. Kept/held output is the source's exact words, unmasked even over the cap. It takes no substitution rolls and prevents inner edits. Adding recognition records must not shift the existing pass's other choices.
- Every substitution and kept spot ends its alternatives with a plain choice. At a substitution it restores the original source wording; at a kept spot it uses the concept's correct sentence form through the shared renderer, never a guessed display-name splice. Plain choices are explicit only, with weight zero. Source-held choices are distinguished as kind source and remain unmasked; all offered replacement words still respect the dials.
- Each choice has key and kind. Dictionary keys are entry:<id>, construction keys construction:<construction_id>, English keys plain:<concept-or-source>, kept source keys source:<id>, and request-local personal keys personal:<content-digest>. Keys are unique across alternatives and locked, and option_key names an offered key. Existing entry_id/construction_id are retained for cards and joins. Riffs/parts/masks keep v3's owner-local coordinates; construction identities persist within dictionary_id. B2 makers and Result.warnings equality remain mandatory.
- Personal request items are {phrase,term,vulgarity?}, at most50, each string at most120 characters and12 words. The package rejects markup, slots, malformed/empty text and conflicting duplicate phrases. Whole-word matching ignores case and uses the shared inflection/case/article renderer. Default tier is the package swear-list rating; an explicit tier replaces it. Applied at every level without a roll, only inside valid editable prose. They have no dictionary identity, score or evidence and never enter tuning. Responses report provided/applied counts outside tuning. The normal personal_terms input and CLI/MCP forwarding land together; a host's personal_terms_hook is per call, with allow_personal_terms controlling capability. Host-owned lists are never accepted from hosted client arguments.
- ED11 propose suggest_selection(text,span,...translation options), CLI suggest-selection --span START END, MCP aussie_suggest_selection. span is in translated output. Snap to words and whole overlapping changes, map back through actual edit traces and render through the same machinery. Candidates are ordered passed-over, kept, lookup. Multiple source spots are separate suggestions with their own src_span/out_span/reading/ruled_out/options; an overall reading is null when no single reading describes the span. This avoids assigning one meaning to a multi-meaning selection.
- ED13 ruled-out choices are rendered at their actual source spot, not generic headwords. Empty words is valid when nothing fits. A held spot means no exact word exists in loaded dictionaries, not merely a dial rejection. Protections/unclear senses and dialect words are not community waiting meanings. Selecting a different reading retains the inferred reading and records selected_reading; the offered choice still passes all ordinary permissions.
- ED15 near is reserved on a substitution as {concept,differs}; reading remains the waiting source meaning. A relation is curated one-way data with a required dinkum/troppo threshold, never a computed synonym. No automatic near use at Deadset, inside a fence, or where an exact word exists. Preset news/instructions/technical/official/custom disable it. The substitution probability has its own graded multiplier. Lookup citations live under meanings[*].near with kind near, concept, plain, differs, setting and word cards; the parent identifies the waiting meaning. All relations are visible even at Deadset, while word cards retain other permissions. No new match_kind is introduced. Near candidates are not labelled ruled out.
- ED14 list_concepts returns {concept,plain,entry_count} rows with stable concept-ID order and standard pagination/envelope. list_entries(concept=...) filters by that concept, intersecting other filters/dials. Counts equal that filtered eligible total. plain is complete final reader-facing en-AU wording for the meaning's name, not an ID or template. Curatorial provisional status does not require the site to complete or rewrite it. Waiting and omitted-only meanings stay separate.

## Review questions; work continues independently

1. Confirm the explicit choice keys/kinds, particularly source/plain/personal, and option_key rather than the old entry_id ?? construction_id shortcut. They are needed because personal/English choices have neither dictionary identity.
2. Confirm selection suggestions grouped by spot when a selection includes multiple meanings; each group carries the replacement coordinates.
3. Confirm near citations nested under the waiting meanings, retaining a distinct role from ruled_out.
4. Personal explicit tiers determine eligibility. Proposed masks retain lexical word ratings for optional display hiding rather than treating personal words as scored dictionary entries; please flag any site rendering expectation that differs. Source's own kept/held words always have empty masks.

These are coordination questions for the site via Rob. They do not pause independent implementation, near-data work or EW4 calibration. Any actual new policy or hard-to-undo action still needs Rob. No staging/main/tag/release/deploy is authorised by this bundle.
