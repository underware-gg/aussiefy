# DD-061: aim and cap dial goals

Status: accepted, Rob’s 19 November 2026 brief.

Readers can ask for the rudeness and embellishment dials as goals. `dial_mode=aim` favours the nearest
permitted tiers and Dinkum/Troppo colour. `cap` preserves existing profiles and seeded translations and
remains the toolkit default; the site sends its choice explicitly. This is one request option, not a new
level. It is forwarded by all adapters, including Markdown, selection and retelling tools.

Keep permissions and preference separate. Resolve document permissions first; aim cannot use garnish a
form excludes. Exact caller overrides remain authoritative. New tuning lives in dial-goals.yaml. Eligible
tier groups are balanced by catalogue size so numerous clean synonyms do not outvote a stronger stop.
Within them, semantic fit, metadata, repeat and tuning weights still matter. Garnish uses one mixed pool,
not clean-first channels. Clean choices keep positive probability and existing budgets/gaps limit density.

Cap’s selection policy remains intact; the separately requested gratitude and lookup bug fixes also apply to cap. The 288-row before/after baseline and seeded voice calibration
are in research/dial-goals-2026-11-19. Frozen v4 schemas are unchanged. Request mode is retained by callers
alongside the other dials, not smuggled into a new response field or a silently changed replay packet.

The separate short-query defect used the contraction fragment don as a shared anchor. Use the existing
token normalisation and inflections for that semantic evidence. Do not substitute a new global threshold
for correcting false evidence. Both scalar and batched lookup follow this rule.

Authored following-preposition evidence permits a greeting complement without swallowing it. THANKS adds
for-context patterns; noun gratitude and causal thanks-to do not gain an interjection reading.
