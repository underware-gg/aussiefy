# Design review 2: architecture (2026-10-12)

The second review, run after the first pass (`design-review-2026-10-12.md`) landed. The brief from the project
owner: further architectural cleanup in line with the principles: humble objects, composability, clear
interfaces, Python module structure. Breaking renames are allowed. Six reviewers (premise, structural,
code smells, efficiency, defensive, completion) covered the whole package, its tests and scripts; each
finding below was traced in the code, and several were reproduced (noted). Convergence is the number of
reviewers who raised it independently.

Not carried forward:
- **Subpackages (`engine/`, `toolkit/`).** The structural reviewer recommends against them: a flat package with a documented and tested layering is right-sized. The layering test (L1) enforces it instead.
- **A shared `PolicyArgs` object.** Ceremony: the flat keyword arguments are the agent-facing contract. Keyword-only parameters (H1) fix the ordering problem.
- **Caching inside lint and lookup for speed.** Both run in 50-75 ms, well under an API round-trip. Their repeated work goes away with M2 and M3, not with more caches.
- **Moving the rewriter to a post-pass (`draft()` / `finish()`).** The engine garnishes each sentence after its rewrite, so a post-pass would change the pipeline's order. The `Rewriter` Protocol (M1) gives the boundary a declared interface at a fraction of the cost.

Order of operations: H4 and H2 (small, user-visible) → H1 (the vocabulary everything else uses) → M6's tests, so the refactors after them are pinned → M2 → M3 → M4 → M1 → M5 → H3 → M7, M8, M9, M10 → the Low items.

## What's done well

- **`policy.roll`**: pure, context-keyed randomness; the engine is deterministic and testable without mocks.
- **`Policy` / `Effective`**: a frozen, validated request and its resolved value (only the field names need aligning).
- **`claude.py`** as the one SDK seam, with the SDK optional and `client=` injectable everywhere; `Cache(None)` turns caching off.
- **`yarn.brief` / `dispatch_tool`**: the API loop is a humble shell; hand-run tools and tests reuse the core. Its unknown-tool and missing-argument guards have a real second caller (the research CLI).
- **`translator=` on every toolkit function, with one cached `default_translator()`**: cheap injection that pays for itself.
- **`mcp_server.py` as a thin adapter, held in step by introspection** rather than code generation.
- **The loader collects every error and raises once**; `RoundPlan.write` validates in a scratch copy (byte-identical re-apply verified); `models.load_config` refuses to read a corrupt config as empty.
- **The toolkit returns JSON-ready dicts and the engine returns dataclasses with `to_dict()`**: the right split. The fixes are to key consistency, not types.
- **The libyaml loader** gives identical results on all 18 data files (verified) at a quarter of the load time.
- **The tests check behaviour**: goldens across levels and seeds, rounds tested for idempotence and refusal, the CLI through `main()` with exit codes, the yarn loop against a scripted client. No stubs or TODOs.
